0. REVISED PIPELINE AND WHAT GETS RERUN
-----------------------------------------------------------------

grid search -> top-10 variants -> validation preds (NEW) -> validation Borda
            -> selector -> combiner -> test evaluation

  selector (after the top-10, design choice):   combiner:
    - Borda top-k (validation)                    - MEAN
    - random-k                                    - IRWM
    - bottom-k                                    - NN (trained on out-of-fold preds)
    - diversity-aware (greedy)

Step-by-step status:
  [KEEP]  Grid search -> top-10 variants per model. NO new grid search.
  [KEEP]  Single variants: test predictions + metrics (saved). Only recompute
          metrics from saved predictions if clipping is added. No retraining.
  [NEW]   Single variants: VALIDATION predictions. The only new training.
          - Traditional (LR, SVR, RT, RF, KNN, KRR): 5-fold out-of-fold on each
            run's training set (fit on 4/5, predict 1/5), same hyperparameters.
          - DeepPerf / HINNPerf: train each variant on 2/3 of the run's
            training set, predict the remaining 1/3 (their own split).
  [RERUN] Borda ranking on validation metrics (multi-metric, as before).
  [RERUN] Selector (top-k, random-k, bottom-k, diversity-aware).
  [RERUN] Combiner + ensemble test evaluation (NN on out-of-fold preds).
  [RERUN] Analysis; all results re-reported.

Why validation predictions and not the saved CV score: grid search kept only
one number, the mean CV MAE ("Rank"). Without predictions we cannot compute
validation MRE/MBRE/MIBRE for Borda, score ensembles on validation, train the
NN on held-out predictions, or measure diversity for the selector.

    10.0 MRE with test order vs 17.5 with CV order.
  - Fix: validation Borda (section 0). In the response: say it honestly,
    show an old-vs-new table. Do not promise "conclusions unchanged".

R2-C20  How is validation separated from training?                [OK]
  - Traditional: GridSearchCV 5-fold inside the training set.
  - DeepPerf/HINNPerf: 2/3-1/3 split inside the training set.
  - Test set never used for hyperparameters. Describe the full pipeline;
    redraw Figure 2 (R2-C19) with the train / validation / test flow.

R2-C21  NN combiner details                         [OK] no leak, [PARTLY] weakness
  - Weights fit on training data only (main.py:182), but on the members'
    IN-SAMPLE training predictions.
  - Report: one linear layer (= linear stacking), MAE loss, Adam,
    <=600 epochs, early stopping patience 20 on TRAINING loss,
    z-scored inputs and target.
  - Fix: train on out-of-fold predictions (Wolpert 1992; Breiman 1996).

R2-C31  Why is NN worse for strong learners?                       [PARTLY]

    so the combiner learns weights that do not transfer to test.
  - At S1 it fits k+1 parameters on 9-31 points (k=10 -> 11 params, 9 points
    at apache).
  - Check whether the pattern still holds after the out-of-fold fix.

R3-C3, R3-G3, R2-C32, R2-C9  Diversity                   [REAL] gap, good story
  - Never enforced or measured.
  - Error correlation within the top-10 (apache, x264):
      SVR / RF / KRR : 0.98-1.00 (no diversity)
      LR             : ~1.00 (0.75-0.91 at small sizes)
      KNN            : 0.84-0.92
      RT             : 0.56-0.84
      DeepPerf       : 0.53-0.83 (top-10 = mostly one architecture, different lambda)
      HINNPerf       : 0.71-0.86
    Gains appear where errors differ.
  - Use ERROR correlation as the main measure (prediction correlation is
    ~1 for any good model and is misleading).
  - Plan: error correlation, prediction correlation, ambiguity
    (Krogh & Vedelsby) per ensemble; scatter diversity vs gain + Spearman.
  - Can be done NOW from saved predictions.

R3-C6(b,c), R3-C7, R3-G2  Random-k, bottom-k, ablation             [REAL] gap
  - Selectors inside the top-10 pool; compare at k = 2..9
    (at k = 10 all selectors give the same ensemble).
  - random-k: fresh random subset per run (30 runs = 30 draws).
    Ranking-free -> can be done NOW from saved predictions.
  - bottom-k: weakest k by validation Borda = "weaker but still tuned"
    members; state that in the paper. Needs the validation ranking.
  - Ablation table: best single -> random-k -> bottom-k -> top-k ->
    diversity-aware, each x MEAN / IRWM / NN. Isolates selection vs
    ensembling vs combination rule.

R3-C6(d)  Diversity-aware selection                                [REAL] gap
  - Selector applied after the top-10 (design choice, before the combiner).
  - Greedy forward selection minimising validation error and/or error
    correlation (Caruana et al. 2004).
  - Must use VALIDATION predictions (in-sample predictions are useless for
    RT/RF/KNN, which fit their training data almost perfectly).

R3-C6(a)  Justification of Borda                                   [OK] text
  - Merges the four metrics without favouring MRE; cite prior use.
